# Project Guidelines

VillageCraft — a Vite + React + TypeScript app that procedurally generates a 3D voxel village using Three.js (`@react-three/fiber`, `@react-three/drei`; `three-bvh-csg` for hollow wall shells). See [spec.md](spec.md) for the original functional spec (French).

## Build and Test

- `npm run dev` — start Vite dev server
- `npm run build` — `tsc -b && vite build` (build fails on type errors)
- `npm run typecheck` — `tsc -b --pretty false`
- `npm test` — Vitest (`vitest run`); tests live next to the code as `*.test.ts` (grid logic, cell utils, `buildVillage`). `npm run test:watch` for watch mode.
- `npm run lint` — oxlint (`--deny-warnings`), config [.oxlintrc.json](.oxlintrc.json): migrated from the former ESLint setup (`@eslint/js` + `typescript-eslint` recommended + `eslint-plugin-react-hooks` recommended, React Compiler rules such as `set-state-in-effect` included — oxlint has them natively as `react/*`). ESLint was dropped because `typescript-eslint` blocked TypeScript 7; oxlint doesn't use the `typescript` package. The lint is **type-aware** (`options.typeAware`, via `oxlint-tsgolint`, built on TypeScript 7): the `typescript-eslint` `recommended-type-checked` rules (`no-floating-promises`, `no-unsafe-*`, `no-unnecessary-type-assertion`…). Beware `oxlint --fix`: tsgolint flagged `` `${a ? 'front' : 'back'}${…}` as keyof … `` as unnecessary while `tsc` needs it — use `as const` there. Fix findings rather than disabling rules; a justified `eslint-disable-next-line` with a comment is acceptable — oxlint honours it (see `renderTick` in `App.tsx`).
- `npm run fmt` / `npm run fmt:check` — oxfmt (Prettier-compatible), config [.oxfmtrc.json](.oxfmtrc.json): single quotes, 120 columns; `spec.md` is excluded (plain text that oxfmt would turn into lists). Format before committing — CI fails otherwise. Line endings are LF everywhere (`.gitattributes`), Windows included, so `fmt:check` passes locally. The bulk reformat commit is listed in `.git-blame-ignore-revs` (`git config blame.ignoreRevsFile .git-blame-ignore-revs`).
- CI: [.github/workflows/ci.yml](.github/workflows/ci.yml) runs format check, lint, typecheck, tests and build on pushes to `dev` and on PRs; the Pages deploy (`deploy.yml`, on `main`) runs lint + tests before building. Node 22.

## Architecture

- **Grid state & procedural generation**: [src/villageGrid.ts](src/villageGrid.ts) owns the 3D `GridCell[][][]` and `recomputeProceduralLogic()`, which assigns each cell's `BlockType` (`Empty`, `Foundation`, `Wall`, `WallWithWindow`, `Roof`, `Arch`) by inspecting neighbours. **Always go through this recompute after any grid mutation** — never patch `cell.type` directly. The grid instance lives in `App`'s `useState`, so a hot update would keep running the old rules: `villageGrid.ts` ends with `import.meta.hot?.accept(() => window.location.reload())` — keep it.
- **Neighbour/shape queries**: [src/utils/cellUtils.ts](src/utils/cellUtils.ts) — always query neighbours via `getCell()`/`hasOccupiedCell()` on a `CellLookup`, never index the raw grid array directly. The lookup is rebuilt per recompute; don't cache it across mutations.
- **Grid mutations go through the controller**: after mutating the `VillageGrid` (add/remove/clear/generate), call `useGridControllerStore.getState().commit()` — it records an undo snapshot (`History` in [src/history.ts](src/history.ts), states = `exportBlocks()`) and triggers the scene refresh. Don't call the refresh callback directly. Undo/redo restore via `grid.replaceBlocks()`, which keeps unchanged cells from replaying their spawn animation. Resizing the grid (new `VillageGrid`) resets the history.
- **Share links**: [src/store/shareLink.ts](src/store/shareLink.ts) encodes `{ gridSize, blocks }` as `#v=<base64url>` (1 byte per value, format version first — bump it if the layout changes). `consumeSharedVillageLink()` runs in `main.tsx` before the first render. Grid bounds live in [src/config/gridConfig.ts](src/config/gridConfig.ts).
- **Grid is pure occupancy + shape**: `VillageGrid` knows nothing about colors or the UI store. It persists via `exportBlocks()`/`importBlocks()` (real blocks in placement order, auto-roof caps excluded) — used by [src/store/villageStorage.ts](src/store/villageStorage.ts) (localStorage) and by grid resizing in `App.tsx`.
- **Render settings**: every style value the geometry depends on (colors, roughness, roof/tower/corner shapes) is a [`RenderSettings`](src/render/renderSettings.ts) object passed to `buildVillage()` and exposed to builders as `ctx.settings`. **Builders and `cellUtils` must never read `useControlStore`** — to add a setting, add it to the store slice, to `RenderSettings` and to `pickRenderSettings()` (the compiler flags a missing key).
- **Rendering pipeline (static merge)**: cells are NOT rendered as individual React meshes. Each `BlockType` has a pure _parts builder_ in `src/render/cells/` (`standardCellParts`, `wallWindowCellParts`, `roofCellParts`, `archCellParts`) that returns `Part[]` — { cached geometry, local matrix, color, material spec } (see [src/render/parts.ts](src/render/parts.ts)). [src/render/buildVillage.ts](src/render/buildVillage.ts) computes one `CellContext` per cell (exposed faces, corner radii, isolation), dispatches to the builder, groups parts by material key and merges each group into a single vertex-colored BufferGeometry. `buildVillage()` (pure, used by tests) merges the whole village per material; the app uses `VillageChunkCache` (same file), which also splits by chunk of `CHUNK_SIZE` × `CHUNK_SIZE` columns (~100 meshes on a 12-grid) and re-merges a chunk only when the hash of its parts (geometry id, matrix, colour, cell centre, spawn time, fall height) changed: builders still run for the whole grid (~20 ms at 12 × 12 — a cell's shape depends on far-away cells, so don't try to guess which cells a click affects), but merging, ~75 % of the cost, now only runs for the 1–2 touched chunks (~25 ms per click instead of ~90). If `mergeParts` starts reading a new part field, add it to `hashParts`, or unchanged-looking chunks will keep stale geometry. [src/components/VillageMeshes.tsx](src/components/VillageMeshes.tsx) keeps one cache per instance, shares one grow-material set per material key across chunks, and disposes only the geometries that were replaced. Rebuild happens only on grid mutations, never per frame.
- **Realistic look (sky, landscape, light, grading)** — everything is procedural, no texture and no UVs (merged geometries have none):
  - **Sky**: [src/components/SkyDome.tsx](src/components/SkyDome.tsx), a world-space dome drawn at the far plane (`gl_Position = clip.xyww`, no depth write, so N8AO skips it): `skyTopColor` → `skyHorizonColor` by elevation, sun disc + halo in the direction of the directional light (it is the moon in the night ambience — same light), fbm clouds, stars when the zenith is dark. It replaced the screen-space gradient, which could not stay still under a turning camera once the ground reached the horizon.
  - **Landscape**: [src/render/landscape.ts](src/render/landscape.ts) (pure, tested) — `terrainHeight()` is exactly 0 up to `flatRadius` (= camera `maxDistance` × scene scale + 4: **the camera must never be able to go under a hill**), rolling hills beyond; `scatterTrees()` is a deterministic, capped (`MAX_TREES`) scatter of groves outside the grid (`TREE_CLEARANCE`, sparse near the village so they don't hide facades). [src/components/Terrain.tsx](src/components/Terrain.tsx) is the meadow (top flush with y = 0; it replaced the floating diorama slab) and [src/components/Trees.tsx](src/components/Trees.tsx) two `InstancedMesh`es (broadleaf, conifer). Both are decor: never raycast — clicks are caught by an invisible plane (`colorWrite={false}`). Fog (`fogFar` 110 by default) is what blends the landscape into the sky: keep `fogColor` ≈ `skyHorizonColor` in ambiences.
  - **Surface detail**: [src/render/surfaceDetail.ts](src/render/surfaceDetail.ts) — world-space value noise evaluated per fragment. Village materials (`createGrowMaterialSet(params, { detail: true })`, everything but glass and `glow` parts) get albedo blotches/grain/large stains, roughness variation, a bump (`vcBumpNormal`, screen-derivative surface gradient), dirt and moss at the foot of walls (y < ~0.45, not on `'room'` parts), and **roof covering**: any sloped face (0.22 < normal.y < 0.97) outside rooms is treated as a roof pan or spire and gets staggered courses of tiles/slates in world coordinates (continuous across cells) — so don't add sloped decorative faces to walls without expecting tiles on them. The row direction comes from the **facet** normal (`cross(dFdx, dFdy)` of the world position), not the interpolated one: spire pans are smooth-shaded, so the interpolated normal turns across a pan and gave wide tiles on one side, slivers on the other. Keep that code branch-free and NaN-free — screen derivatives are undefined inside an `if`, and a single NaN pixel, once spread by bloom, blacks out the whole frame. The bump slope is clamped (a tile edge is a height step: unclamped it sparkled white on dark slate) and roofs are forced matte. Fine patterns fade with distance and with their on-screen footprint (`fwidth`; they alias otherwise). The two shader variants need distinct `customProgramCacheKey`s: three caches programs by the _text_ of `onBeforeCompile`. Terrain and trees use `injectWorldDetail()` (handles instancing).
  - **Light**: a `hemisphereLight` (sky tint from `ambientColor`/`skyTopColor`, ground bounce from `groundColor` × sun colour — `skyLightColors()` in `VoxelScene.tsx`) instead of a flat ambient, plus the directional sun (low and warm by default, for long shadows and one bright / one dim facade from the starting camera).
  - **Post chain order matters**: AO → bloom (linear HDR, half-float buffer) → `ToneMapping` (AgX) → [`ColorGrade`](src/components/ColorGrade.tsx) (contrast pivoted on mid-grey + saturation, clamped) → noise → vignette. `@react-three/postprocessing`'s composer disables the renderer's own tone mapping, so without the `ToneMapping` effect nothing is tone-mapped; exposure is `gl.toneMappingExposure` (`exposure` in the store). Don't swap `ColorGrade` for `BrightnessContrast` + `HueSaturation`: behind AgX they left [0, 1] and burnt sunlit areas to pure white; and noise before tone mapping showed as white specks in night shadows.
  - **Stone walls**: wall bodies carry `masonry: true` in their `MaterialSpec` (hollow shell, arch body, tower parapet and merlons, walkway parapets and pierced merlons, chimney stacks — never joinery, dressed stones, quoins or frames). That flag is part of `matKey` (suffix `|m`) and selects a shader variant (`VC_MASONRY` define, `createGrowMaterialSet(…, { masonry })`) that lays castle stonework on their vertical faces: roughly squared rubble in courses of unequal height (`vcCourseBed`, beds jittered around a 12-per-unit grid), stones of varying length (`vcStoneHead`, module and offset per course), wavy thick lime joints, worn rounded corners, per-stone tone and tool pitting, a slightly cushioned face. **Keep it irregular**: a first version with regular moulded bricks in monk bond read as 19th-century, not as a castle. **Geometry is untouched**: the pattern is computed in world coordinates (courses from y only, so they agree on every face; vertical joints from x or z by dominant normal axis), so it runs unbroken across the cells of a merged building and nothing changes for the static merge. On rounded corners the run is continued in arc length (smooth normal angle, tower radius); the axis switches on the diagonal, where the relief is muted (its height step drew a dotted vertical line). Cavity faces of the shell (rooms, window reveals) stay plastered — same bounds as the interior light. The stone colour is `wallBaseColor`. The pattern fades to its average tone with its on-screen footprint, and its relief fades much earlier (its screen derivatives drew a diagonal moiré at a distance).
  - **Joinery & smooth contours**: doors are oak planks over a dark backing with wrought-iron strap hinges and a pull ring, window glazing bars are dark oak (`wallWindowCellParts.ts`; door tint varies per cell by coordinate hash). Extruded cell contours (`shapedBoxGeo`, the CSG cavity prism) get `toCreasedNormals(…, CONTOUR_CREASE_ANGLE)`: arc facets (9° apart) share normals, right angles stay sharp — with flat facets every tower showed vertical bands under the sky light.
  - **Interior decor**: ground floors are flagged in stone, upper floors boarded; four ceiling joists per cell run across the beam (`interiorParts.ts`). Windows get drawn-back curtains on the room side (`curtainParts` in `wallWindowCellParts.ts`, marked `'room'`; the first fold bites 4 cm into the opening — fully beside it, the wall hid them from the street; one colour per house). Furniture adds: tableware on the dining table, a writing desk upstairs, tapestries on blind walls, a cauldron, flames (`glow`) and a log pile at the fireplace, a pillow and footboard on beds. **Any `glow` part emitted by `furnitureParts` means a fireplace** (the test relies on it — the table candle is unlit), and nothing may stand in a door's passage (stools at the table ends were removed for that). The room lamp has its own paler colour (`INTERIOR_LAMP_COLOR`) and the glass veil is light (`GLASS_GLOW_INTENSITY` 0.1): with the saturated window-glow orange, every interior read as one flat amber surface at night.
- **Window glow & interiors**: parts with `glow: true` in their `MaterialSpec` (window glass, arrow slits) form their own merged group whose emissive is driven by `windowGlow` in `VillageMeshes` — imperatively, then `invalidate()`. Window glass is clear and light (`WINDOW_GLASS_OPACITY` 0.3 in `wallWindowCellParts.ts`), day and night, because interiors are meant to be seen from the street (future interior furniture — never hide or cull interiors); its emissive is divided by its opacity so that, once alpha-blended, the glow is `GLASS_GLOW_INTENSITY` (a light warm veil, the room stays visible). **Interior light**: the walls block the sun, so rooms are lit by a fake lamp in the shader (`injectInterior()` in [src/render/growMaterial.ts](src/render/growMaterial.ts), main material only, not the depth material), placed at the flames of the room's chandelier (`INTERIOR_LAMP_Y`, `chandelierParts()` in `interiorParts.ts`: chain, iron ring, 4 candles; flames are `glow` parts with a dark wick colour, so they only light up with `windowGlow`). **One chandelier per room, not per cell**: `assignRoomLamps()` ([src/utils/roomLamps.ts](src/utils/roomLamps.ts)) flood-fills rooms (hollow cells of one storey, 4-connected — the same cells whose shared side is `open`), hangs the first chandelier in the most central cell and adds one only for cells more than `LAMP_REACH` (2, Chebyshev) cells from every chandelier, so up to 5 × 5 a room has one; each cell is lit by the nearest one (`CellContext.chandelier` says whether the cell carries it). The shader light falls off horizontally (`LAMP_FALLOFF`, half at 2 cells). Lit parts are **explicitly marked** with `Part.interior` (`InteriorKind`, `asInterior()` in `parts.ts`), never guessed from position — stones embedded in the wall used to catch the light on their edges: `'room'` = furnishings (floor, ceiling, beam, chandelier, future furniture: mark them `'room'`), every face turned towards the lamp is lit; `'shell'` = the hollow shell body, lit only inside the cavity (between floor and ceiling, and less than 0.5 − `WALL_T` from the centre **along the face normal only** — testing |x| and |z| together left a dark 8 cm strip of interior wall on each side of every seam between two cells of a room, where the wall runs to the cell edge along an `open` side; window reveals are thus lit up to the outer face, like light spilling through the glass). Stones, quoins, frames, glass, flames: unmarked, never lit. The mode (0 none, 1 shell, 2 room — only in hollow cells) is stored in `aCell.w` = code × 4 + mode, code = fall × 100 when mode is 0 (only roofs fall), else the offset to the room's chandelier cell, `(dx + 16) × 32 + (dz + 16)`; all of it is hashed by `VillageChunkCache` (adding a cell to a room re-merges the chunks of the whole room). The fragment adds `albedo × uInteriorLight × max(dot(normal, toLamp), 0)` to its emissive — computed **per fragment** (the vertex shader only passes cell-local position, lamp, normal and mode): interpolated per vertex, it followed the large irregular triangles CSG leaves on the shell walls and drew light bands across interior walls. `VillageMeshes` sets `uInteriorLight` (shared uniform object per material set): `interiorFill` (store, neutral day fill) fading into a warm lamp as `windowGlow` rises. A chandelier costs ~250 vertices. **Furniture**: `furnitureParts(ctx, openings)` ([src/render/cells/furnitureParts.ts](src/render/cells/furnitureParts.ts), called from `interiorParts`, which receives the cell's openings from `shellParts`) — deterministic per cell (hash of coordinates): under the room's chandelier a table + benches (ground floor) or a rug (upper floors); doors and fireplaces are planned **per room** (chandelier zone, `lampZones()`) before any wall is built, by `buildVillage` between computing all `CellContext`s and running the builders. **Doors**: `planDoors()` ([src/render/cells/openings.ts](src/render/cells/openings.ts), result in `CellContext.doorFace`) — one per ground-floor zone, not one per cell (a row of merged houses used to show a door on every cell), on the exposed face of a `WallWithWindow` cell nearest the chandelier, a flat wall preferred over a rounded corner, never on a rampart; tested. **Fireplaces**: `planFireplaces()` (`furnitureParts.ts`, result in `CellContext.fireplaceFace`), `FIREPLACE_CHANCE` of zones (~75 % ground floor, ~45 % upstairs in practice), on the zone cell nearest the chandelier whose wall is not `open`, not a door or slit, not in a rounded corner, and whose column is topped by a gable roof; any of the 4 walls — a ceiling beam that ends on that wall stops against the hood (`HOOD_REACH`, `interiorParts`; only accepting walls parallel to the beam left a 1-cell-wide row with nothing but its pierced gable walls); a blind wall is preferred, else a window wall **loses its window** (`openingKindsOf(ctx, fireplaceFace)` in `openings.ts`, shared by `wallWindowCellParts` and the planner) as long as the room keeps another window. **Flues**: roof chimney stacks are no longer random — `buildVillage` gives the roof cell at the top of each fireplace's column a flue (`CellContext.flues`, cell coordinates, `FLUE_OFFSET` from the centre towards the fireplace wall, deduplicated for stacked fireplaces), and `gableRoofParts({ flues })` draws a stack there, from under the pan to above the ridge (tested: one stack per fireplace column/wall, none without a fireplace). Accepting blind walls only gave 0 fireplaces on ground floors: every exterior face there has a door or a window. A fireplace is centred on its wall and takes its two corners; embers are a `glow` part; against walls, one slot per corner (`SLOT_OFFSET` along the wall, `WALL_GAP` from it): chests, cupboards, barrels, shelves with books and pots, workbenches (ground floor), one bed per cell upstairs (a bed spans the room, so it takes both corners on its side), shelves, or nothing. Never against an `open` side or the wall of a door; under a window or slit only pieces lower than the sill (`LOW_MAX_H`); no wall pieces in towers (rounded contour) or in a rounded corner. Scale: 1 unit ≈ 2.8 m (the 0.71 door is ~2 m). Boxes and 8-segment cylinders only (~24 vertices per welded box); with chandeliers a generated 12-grid village is ~400 k vertices. `furnitureParts.test.ts` intercepts the real calls during `buildVillage` (`vi.mock`) to check, over generated villages: inside the cavity and rounded corners, door passage clear, nothing above the sill in front of a window, nothing against open sides, vertex budget, determinism. New furniture: add a `Piece` builder (back against +z, standing on y = 0) and pick it in the slot loop. Bloom's threshold (0.85) is set so that only those lit windows bloom.
- **Changing a persisted default**: `persist` stores the whole control state, so a new default never reaches existing users on its own. Bump the store `version` and extend `migrateControlState()` in [src/store/controlStore.ts](src/store/controlStore.ts): replace a key only if it still equals the old default, delete removed keys (tested in `controlStore.test.ts`).
- **Ambient occlusion**: N8AO via [src/components/AmbientOcclusion.tsx](src/components/AmbientOcclusion.tsx), imported **dynamically** by `VoxelScene` once `aoEnabled` is on, and mounted as a regular `EffectComposer` child (no `Suspense` — the composer only rebuilds its passes when its children change). The `EffectComposer` is keyed on whether the AO pass is mounted: adding a depth-texture pass to a composer that has already rendered leaves its MSAA depth renderbuffer in DEPTH24 while the texture is DEPTH32F, and the MSAA resolve blit then fails every frame on strict drivers (Metal/macOS: `glBlitFramebuffer: Depth/stencil buffer format combination not allowed`) — keep the key. `n8ao` has its own chunk group in `vite.config.ts` (`priority`, `includeDependenciesRecursively: false`); otherwise rolldown folds it (~83 kB gzip) into the startup `r3f` chunk. It is also declared side-effect free (`treeshake.moduleSideEffects`): `@react-three/postprocessing` re-exports its own N8AO effect, and without that rule the `r3f` chunk kept a bare `import "./n8ao…"`, so the chunk was preloaded and run at startup anyway — check `dist/index.html` has no `n8ao` modulepreload after touching the build config. The Tweakpane panel is `React.lazy`-loaded from `App.tsx` for the same reason. Types for `n8ao` are declared in `src/n8ao.d.ts`.
- **On-demand rendering**: the `Canvas` uses `frameloop="demand"` — a frame is drawn only when R3F props change, OrbitControls moves (drei invalidates) or something calls `invalidate()`. Anything animated per frame must keep calling `invalidate()` while it runs (see the spawn animation in `VillageMeshes.tsx`), otherwise it freezes after one frame. Exception: when the Debug perf monitor is on, the loop switches to `"always"` (r3f-perf samples through R3F's global loop callbacks, which only run on rendered frames).
- **Geometry cache**: [src/render/geometryCache.ts](src/render/geometryCache.ts) — every geometry (box, rounded box, cylinder, extruded cell contour, window frame-with-hole, gable…) is built once per parameter combination and shared. Never mutate a cached geometry; the merge copies its attributes. `getGeo()` strips every geometry to position + normal and welds it (`mergeVertices`): cached geometries are **indexed**, and `mergeParts` copies their index with an offset (Uint16 per merged group when it fits). Only ~36 % of a village's triangle corners are unique vertices. **Merged vertex format** (`mergeParts` in `buildVillage.ts`, read by the shader in `growMaterial.ts` — change both together): position Float32 × 3, normal Int8 normalized × 3, color Uint8 normalized × 3, `aCell` Int16 × 4 = (cell pivot × 2, fall height × 100) — pivots are always on half units, so exact — and `aSpawn` Float32: 33 bytes per vertex instead of 56. A generated 12 × 12 village is ~390 k vertices / ~15 MB (it was 1.1 M / 62 MB). The cache is an LRU bounded to 1500 entries (a full village uses ~350); cached geometries are never rendered directly, so eviction needs no `dispose()`. **Vertex budget**: `roundedBoxGeo` caps its segments by radius (1 segment for r ≤ 0.015, max 2 otherwise) — a smoothness-4 rounded box is ~2 900 vertices (non-indexed), and these tiny parts once made up ~94 % of the village's vertices for no visible gain. Keep new small decorative parts cheap (a village cell is ~1.8 k welded vertices today). Window frames use a shape-with-hole extrusion, not CSG; CSG is used only for hollow shells (below), cached like any other geometry.
- **Hollow blocks**: `Wall`, `WallWithWindow` and `Foundation` cells (`isHollowType()` in `cellUtils.ts`) are masonry shells, not solids: `hollowShellGeo(radii, hollow, openings)` in `geometryCache.ts` = `shapedBoxGeo` − inner volume − openings, computed with `three-bvh-csg` once per combination (`three-bvh-csg` ≥ 0.0.18 needs `three-mesh-bvh` ≥ 0.9, a direct dependency, while drei keeps its own nested 0.8 copy; npm cannot resolve both bumps in one `npm install`: install `three-mesh-bvh` first, then `three-bvh-csg`). `getHollowShape()` gives `CellContext.hollow` (null for roofs/arches): each side is `exterior` (wall, openings allowed), `open` (hollow neighbour → no wall, one continuous interior per building) or `partition` (roof/arch neighbour → blind wall); a pillar is kept at an inner corner whose two sides are open but whose diagonal is not hollow (L-shaped buildings), otherwise the neighbours' outer walls leave a hole; floor **and** ceiling `FLOOR_T` in every block, even under another hollow block (2 × `FLOOR_T` slab between storeys): all ceilings of a storey are at the same height. An open ceiling under storeys and a closed one under roofs left a `FLOOR_T` step where the edges of abutting roofs (eaves, panels) hung down; for the same reason `gableRoofParts` drops the eave fascia on a side that butts against a neighbour (`eavePos`/`eaveNeg`). Interiors are finished by `interiorParts()` ([src/render/cells/interiorParts.ts](src/render/cells/interiorParts.ts), called from `shellParts`): wooden floorboards with seams every 0.25, a plastered ceiling and one beam per cell. Floor and ceiling use `hollowShellGeo`'s sibling `hollowSheetGeo()`, which follows the same inner contour (rounded towers, corner pillars) and stops exactly at the cell edge on `open` sides so neighbouring sheets meet without overlap. The shell body is the only part with `doubleSide: true` in its `MaterialSpec` (its own merged group, `DoubleSide`, `shadowSide: BackSide` so shadows are unchanged): walls and floors are thinner than the camera's near plane, so a camera inside them would otherwise see through. Walls are `WALL_T` thick and follow the rounded contour (inner radius = r − `WALL_T`). Windows, doors and arrow slits are real holes (`OPENING_SIZES`): glass, door panel and slit back are set inside the wall thickness, frames stay on the outer face with a hole aligned on the opening. Openings are cut with **square** boxes: a rounded cutter blew a 4-window shell up to ~14 k vertices (CSG triangle splitting), vs ~1.6 k (budget tested in `hollowShell.test.ts`).
- **Scene/interaction**: [src/components/VoxelScene.tsx](src/components/VoxelScene.tsx) (R3F canvas, OrbitControls, click-to-add/remove), reading scene/lighting/postFX values from [src/store/controlStore.ts](src/store/controlStore.ts). Only a large invisible ground plane has pointer handlers; its event's `ray` is then walked through the voxel grid by `raycastVoxels()` ([src/utils/voxelRaycast.ts](src/utils/voxelRaycast.ts), DDA) so the click targets the first block under the cursor, not the ground behind it — never raycast the merged meshes (~1 M vertices, no BVH). `targetColumn()`: demolish / build on a top face → that column; build on a side face → the neighbouring column. `GestureTracker` counts pressed pointers (window capture phase, so it sees pointerups captured by OrbitControls): a multi-touch gesture is never a tap. Resizing the grid derives every new size from the village as it was before the first resize (`resizeSource` in `App.tsx`), so shrinking then growing back restores cropped blocks until the next edit. `App.tsx` memoizes `cells` on the render tick so pointer-move re-renders never trigger a merge rebuild.
- **Toolbar & overlays**: [src/components/Toolbar.tsx](src/components/Toolbar.tsx) (tools, history, generate/clear, ambience picker, share, screenshot, help), [src/components/HintCard.tsx](src/components/HintCard.tsx) (first-run help, touch-aware). Their UI state (active tool, hint dismissed, screenshot capture callback) lives in [src/store/uiStore.ts](src/store/uiStore.ts). Ambience presets are plain data in [src/config/ambiencePresets.ts](src/config/ambiencePresets.ts), applied with `useControlStore.setState(preset.settings)`. The screenshot uses R3F `advance()` + `toDataURL()` in the same task (see `ScreenshotBridge` in `VoxelScene.tsx`) — don't enable `preserveDrawingBuffer` for it. UI colors are CSS tokens (`--ui-*`) in `styles.css`, which also themes Tweakpane through its `--tp-*` variables.
- **Control panel**: [src/components/TweakpanePanel.tsx](src/components/TweakpanePanel.tsx) owns the Tweakpane `Pane` lifecycle and composes one `register*Controls(pane)` module per domain from `src/controls/` (grid, lighting, sky/fog, camera, post-FX, debug, actions) — each is a plain function returning a disposer, built with `registerStoreFolder(pane, { title, fields })` from [src/controls/storeFolder.ts](src/controls/storeFolder.ts): a declarative list of `[storeKey, tweakpaneBindingParams]` written straight to the store (`[x, y, z]` tuples are edited as Tweakpane 3D points), and a folder only refreshes when one of its own keys changes. Add a setting by adding its key to the store (+ default, + migration if persisted users need it) and one line in the relevant module; add a new domain with one new module file + one line in `TweakpanePanel.tsx`'s `disposers` array. Village actions live in the toolbar, which reaches the imperative `VillageGrid` through [src/store/gridControllerStore.ts](src/store/gridControllerStore.ts) (non-persisted) rather than prop-drilling.
- **Decorations & protected zones**: [src/config/protectedAreasConfig.ts](src/config/protectedAreasConfig.ts) defines window/door/arrow-slit exclusion zones; [src/render/cells/stoneParts.ts](src/render/cells/stoneParts.ts) and [src/render/cells/decorations.ts](src/render/cells/decorations.ts) must respect these zones when placing decorative stone/quoins — the `isInProtectedZone` callback stays per-cell-type, don't centralize that logic.

## Conventions

- **Adding a new `BlockType`**: add the enum value in [src/types.ts](src/types.ts), create a parts builder under `src/render/cells/` (return `Part[]` with cell-local matrices; use `geometryCache` helpers), dispatch it in `buildVillage.ts`, and extend `recomputeProceduralLogic()` in `villageGrid.ts` to assign it.
- **Defensive tops (towers, curtain walls)**: `roofCellParts` picks the top of a column from its context, without new `BlockType`s. Isolated roof → tower: slate roof following the tower's own contour (`spireBandGeo`/`towerSoffitGeo`: flared eave then steep cone, colour `spireColor`), or, for ~1 tower in 3 chosen by a hash of its column, a crenellated top with no roof. `isRampart()` in `cellUtils.ts` detects curtain walls (1-cell-thick straight run whose both ends butt against taller columns) → wall-walk + crenellated parapets with arrow-slit merlons instead of a gable roof; `CellContext.isRampart` is also true for the walls below, which get arrow slits and no door. Merlons (`merlonCount` for towers — rounded to a multiple of 4 and laid out symmetrically from the middle of each side, never on the rounded corners where they read as 45° chevrons; `merlonR`, `merlonH`) are rectangular stone, never on a roofed tower — that's how they're used on real enceintes.
- **Roof ridges & junctions**: a gable roof's ridge follows the building, not the cell: `getRidgeAxis()` (`cellUtils.ts`) takes the axis of the longest run of contiguous gable-roof cells (`isGableRoofCell()`: same level, not a spire, not a rampart) through the cell — so ridges are parallel inside a block (valleys between rows) and follow a 1-cell wing; on a tie (square block…) the whole group of contiguous gable-roof cells decides at once — its larger extent, else Z — never cell by cell (a cell that also touched a taller wall used to take the other axis and cross its ridge mid-block); a lone roof cell keeps the axis of its occupied neighbours. A wing meeting another roof at right angles used to butt its open end (a full-height triangle) against that cell's descending pan — a hole. Now a cell adds a half-roof (`gableRoofParts(…, { extent: 'pos' | 'neg' })`, from its centre to that side, no gable) toward each perpendicular neighbour **whose ridge points at it**: T junction, L corner with a single valley, crossing. Parallel neighbours never trigger it — an earlier version merged every cell with neighbours on both axes and crossed ridges all over wide blocks. Eave fascias stay only on sides with no neighbour; a gable's bottom band overhangs like them on a free side and stops at the cell edge next to a neighbour, 4 mm in front of the eave fascias (face at 0.544), so it covers the ends of the pans and side fascias (all at ±0.54) instead of sharing their plane — when coplanar, the pan's bevelled corner pierced it as a light spike at every gable corner; eave fascias are exactly as long as the pans (6 cm longer, they stuck out at every gable corner). At an L corner, the half-roof's pan facing the main roof's gable stops inside the gable's thickness (`panRunPos`/`panRunNeg`) and drops its fascia — it used to run past the gable's foot to the facade, battens and fascia included. Tested by vertical rays across junction boundaries, in a 4 × 2 block, and in front of an L corner's gable (`buildVillage.test.ts`).
- **Arches, paving, walkways**: an arch is a block with nothing below it, which a click can never create (clicks stack on top of the column), so arches are **automatic**, like roof caps: `syncAutoArches()` spans a street 1 or `MAX_ARCH_SPAN` (2) cells wide — never more, a wider street stays open, open at ground level, between two facing buildings that have a **wall** at the arch's level (occupied at y = 0, 1 and 2, so y = 1 is not their roof — an arch resting on the roofs of one-storey houses stood a full storey above their walls with its own roof), one arch per street stretch (consecutive rows with the same gap), in the middle; at a crossroads the X span wins. `recomputeProceduralLogic` runs roofs → arches → roofs: caps are up to date before supports are checked, and an arch that disappears (passage built) must leave room for that column's cap in the same pass — otherwise results depend on click order (a test builds the same shape in 50 random orders). `isSimpleArch` (the type rule) only requires one opposite pair and nothing below. Auto arches (`isAutoArch`) are not user blocks: not exported/saved, skipped by `getTopOccupiedY`/`getTopRealOccupiedY` (a click in the lane builds on the ground, demolition ignores them), and they vanish when their supports go. Test helpers note: `addBlockInColumn` fills gaps from the bottom; the UI path is `getNextPlacementY` + `addBlock`. An `Arch` cell is a solid masonry block whose underside is cut by a segmental arch, with voussoirs + keystone on both faces — no pillars. A multi-cell arch is one arc computed for the whole span (rise 0.42 / 0.66 for 1 / 2 cells): each cell draws its slice (`archBodyGeo(rise, span, slice)`) and the voussoirs whose middle falls in it (`archVoussoirMidX`); the span axis follows the neighbours on each side, the span length the contiguous `Arch` cells, and if nothing is built above, its top depends on the columns around all its cells: if one of its two supports has a gable roof at the arch-top level (y + 1), that roof continues over the arch **in that roof's ridge axis** (the span axis if a continuing roof follows it; else gables on both arch heads, if free) and butts against the other support — an arch roof across the support's ridge butted its open end against that roof's pan (stone merlons must never lean on tiles); else a crenellated walkway like curtain walls (`crenellatedWalkwayParts()`) if one is a tower column (`isTowerColumn`) **and** both supports have a wall at y + 1 (a walkway links two walls — not a spire's foot or thin air); else a gable roof, ridge from support to support (`gableRoofParts()`, exported from `roofCellParts`, `baseY: 1`), if **at least two** of those columns are topped by a gable roof (not a tower, not a rampart); else a plain flagstone deck (`walkwayDeckParts()`). A tower keeps its rounded corners all the way up (its base decides), so a flat arch abutting it would leave a vertical gap in each corner: `abutmentFillets()` fills them with `cornerFilletGeo()` (square minus quarter disc, same 10 arc segments as the tower contour), from the arch's foot to the top of its walkway/parapet, never inside the support (towers are hollow). Merlon arrow slits are real through-slits (`piercedMerlonParts()`: four blocks around the slit), not a dark box. Walkways use `flagstoneParts()` ([src/render/cells/walkwayParts.ts](src/render/cells/walkwayParts.ts)). Ground: `buildVillage(…, ground)` paves every empty ground cell that touches a building, diagonals included ([src/render/cells/pavingParts.ts](src/render/cells/pavingParts.ts)) — lanes, streets and passages under arches — plus any cell under an arch, with one merged cobble tile per cell (`cobbleTileGeo`, 3 variants × 4 rotations picked from the cell position); further out the grass shows.
- **Tower propagation is intentional**: `isTowerColumn()` in `cellUtils.ts` propagates upward — if a block is isolated (no horizontal neighbours), all blocks below it in the column become cylindrical too. Don't simplify this to a per-block check; it's what makes towers look right. `isIsolatedBlock()` (used for roofs) is a separate, non-propagating check — this asymmetry is deliberate.
- **Colors**: base colors come from `settings.wallBaseColor` / `settings.roofBaseColor`; derived tones use `shades()` / `varyColorBrightness()` from `src/colorPalettes.ts`. Any per-cell variation must be deterministic (hash of coordinates) — never `Math.random()` in a builder.
- **Windows**: the "one window per floor between adjacent blocks" rule in `recomputeProceduralLogic()` only looks at neighbours already typed in the current pass (x-1, z-1), so the result depends on shape only, not click order. Keep it that way (there's a test for it).
- **Terrain generation** (`generateTerrain(gridSize, seed?)` in `villageGrid.ts`) uses seeded value noise ([src/utils/noise.ts](src/utils/noise.ts)) for occupancy/height (clusters of buildings, ≥ 40 % of lots filled), empty rows as streets on grids ≥ 6, and rare +2 landmark columns. Same seed → same village (tested).
- **Grid size & scene scale**: bounds live in [src/config/gridConfig.ts](src/config/gridConfig.ts) (max 12). Camera/fog distances were tuned for a 5-grid; `sceneScale()` stretches fog and `maxDistance`, `initialCameraScale()` the starting camera, and `shadowCameraHalfSize()` sizes the sun's orthographic shadow frustum (three's default ±5 only covered ~5 cells).
