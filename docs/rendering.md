# Rendering

How the village is turned into a few merged meshes, and how the scene around it is drawn.

- **Rendering pipeline (static merge)**: cells are NOT rendered as individual React meshes. Each `BlockType` has a pure _parts builder_ in `src/render/cells/` (`standardCellParts`, `wallWindowCellParts`, `roofCellParts`, `archCellParts`) that returns `Part[]` — { cached geometry, local matrix, color, material spec } (see [src/render/parts.ts](../src/render/parts.ts)). [src/render/buildVillage.ts](../src/render/buildVillage.ts) computes one `CellContext` per cell (exposed faces, corner radii, isolation), dispatches to the builder, groups parts by material key and merges each group into a single vertex-colored BufferGeometry. `buildVillage()` (pure, used by tests) merges the whole village per material; the app uses `VillageChunkCache` (same file), which also splits by chunk of `CHUNK_SIZE` × `CHUNK_SIZE` columns (~100 meshes on a 12-grid) and re-merges a chunk only when the hash of its parts (geometry id, matrix, colour, cell centre, spawn time, fall height) changed: builders only run for the buildings that changed: `collectVillageParts` splits the village into buildings (4-connected built columns, arches included — `villageBuildings()`) and keeps each building's placed parts under a signature of its cells (type, auto cap/arch, spawn time), its columns' terrain levels and the ring of columns around it (`buildingSignature()`); settings, relief or world mapping changes clear the whole cache (`environmentKey()`). Everything a builder reads — neighbours, ridges, ramparts, arch supports, rooms, doors, stairs, fireplaces, flues — stays inside the building, so don't add a builder dependency that reaches into another building without widening the signature; `buildVillage.test.ts` checks, edit after edit, that the cached result is byte-identical to a fresh build. Measured with `npm run perf` (`perf/`): a click on a generated 12 × 12 village went from ~160 ms to ~80 ms (24 × 24: ~790 → ~310); what remains is the touched building, the paving (rebuilt everywhere) and merging the 1–2 touched chunks. If `mergeParts` starts reading a new part field, add it to `hashParts`, or unchanged-looking chunks will keep stale geometry. **The build runs in a Web Worker**: [src/components/VillageMeshes.tsx](../src/components/VillageMeshes.tsx) sends the grid through `VillageBuildClient` ([src/render/villageBuild.ts](../src/render/villageBuild.ts)) to [src/render/villageWorker.ts](../src/render/villageWorker.ts), which keeps the `VillageChunkCache` and sends back only the re-merged chunks, their typed arrays transferred (unchanged chunks keep their geometry object on the page); one build at a time, only the latest request kept while one runs, every response applied in order ("kept" chunks refer to the previous one). The world mapping travels as an affine sample (`sampleMapping`), the relief only when it changes (the worker keeps the same object: the building cache keys on it). Without `Worker` (tests) the same host runs in place. **Ground and village change together**: each result comes with the request it built (`BuildDelivery`); `VillageMeshes` reports that request's relief (`onPresent`) and `VoxelScene` draws the terrain, trees, grid lines, camera floor and the shaders' relief uniforms from it, not from the current grid (the click surface and raycasting stay on the current relief) — before this, generating a village showed the new ground under the old village for the ~1 s the build took, then the village popped in. Spawn times of blocks still appearing when the request was sent are shifted by the delivery delay (`retimeSpawns`, on a copy), so their grow animation starts when they show up rather than playing unseen during the build. Measured in headless Chrome on a 12 × 12 village: a click used to block the main thread 130–325 ms, now no long task at all. Everything the worker imports must stay free of DOM and store access (the builders already are). The page shares one grow-material set per material key across chunks, and disposes only the geometries that were replaced. Rebuild happens only on grid mutations, never per frame.
- **Render settings**: every style value the geometry depends on (colors, roughness, roof/tower/corner shapes) is a [`RenderSettings`](../src/render/renderSettings.ts) object passed to `buildVillage()` and exposed to builders as `ctx.settings`. **Builders and `cellUtils` must never read `useControlStore`** — to add a setting, add it to the store slice, to `RenderSettings` and to `pickRenderSettings()` (the compiler flags a missing key).
- **Realistic look (sky, landscape, light, grading)** — everything is procedural, no texture and no UVs (merged geometries have none):
  - **Sky**: [src/components/SkyDome.tsx](../src/components/SkyDome.tsx), a world-space dome drawn at the far plane (`gl_Position = clip.xyww`, no depth write, so N8AO skips it): `skyTopColor` → `skyHorizonColor` by elevation, sun disc + halo in the direction of the directional light (it is the moon in the night ambience — same light), fbm clouds, stars when the zenith is dark. It replaced the screen-space gradient, which could not stay still under a turning camera once the ground reached the horizon.
  - **Landscape**: [src/render/landscape.ts](../src/render/landscape.ts) (pure, tested) — apart from the village relief (see **Sloping terrain** below, which dies out near the grid), `terrainHeight()` is exactly 0 up to `flatRadius` (= camera `maxDistance` × scene scale + 4: **the camera must never be able to go under a hill**), rolling hills beyond; `scatterTrees()` is a deterministic, capped (`MAX_TREES`) scatter of groves outside the grid (`TREE_CLEARANCE`, sparse near the village so they don't hide facades). [src/components/Terrain.tsx](../src/components/Terrain.tsx) is the meadow (`groundHeight()` = hills + village relief; it replaced the floating diorama slab) and [src/components/Trees.tsx](../src/components/Trees.tsx) two `InstancedMesh`es (broadleaf, conifer). Both are decor: never raycast — clicks are caught by an invisible plane (`colorWrite={false}`). Fog (`fogFar` 110 by default) is what blends the landscape into the sky: keep `fogColor` ≈ `skyHorizonColor` in ambiences.
  - **Surface detail**: [src/render/surfaceDetail.ts](../src/render/surfaceDetail.ts) — world-space value noise evaluated per fragment. Village materials (`createGrowMaterialSet(params, { detail: true })`, everything but glass and `glow` parts) get albedo blotches/grain/large stains, roughness variation, a bump (`vcBumpNormal`, screen-derivative surface gradient), dirt and moss at the foot of walls (less than ~0.45 above the terrain — `vcGroundHeight()`, the GLSL twin of `reliefHeight()` — not on `'room'` parts). No roof pattern is painted any more (tiles and slates are geometry, below): a painted one was guessed from the slope of faces and printed notches on the rounded arrises of the stones, then, once restricted to roofs, still drew jagged courses. Keep this shader branch-free and NaN-free where it uses screen derivatives — they are undefined inside an `if`, and a single NaN pixel, once spread by bloom, blacks out the whole frame. The two shader variants need distinct `customProgramCacheKey`s: three caches programs by the _text_ of `onBeforeCompile`. Terrain and trees use `injectWorldDetail()` (handles instancing).
  - **Light**: a `hemisphereLight` (sky tint from `ambientColor`/`skyTopColor`, ground bounce from `groundColor` × sun colour — `skyLightColors()` in `VoxelScene.tsx`) instead of a flat ambient, plus the directional sun (low and warm by default, for long shadows and one bright / one dim facade from the starting camera).
  - **Post chain order matters**: AO → bloom (linear HDR, half-float buffer) → `ToneMapping` (AgX) → [`ColorGrade`](../src/components/ColorGrade.tsx) (contrast pivoted on mid-grey + saturation, clamped) → noise → vignette. `@react-three/postprocessing`'s composer disables the renderer's own tone mapping, so without the `ToneMapping` effect nothing is tone-mapped; exposure is `gl.toneMappingExposure` (`exposure` in the store). Don't swap `ColorGrade` for `BrightnessContrast` + `HueSaturation`: behind AgX they left [0, 1] and burnt sunlit areas to pure white; and noise before tone mapping showed as white specks in night shadows.
- **On-demand rendering**: the `Canvas` uses `frameloop="demand"` — a frame is drawn only when R3F props change, OrbitControls moves (drei invalidates) or something calls `invalidate()`. Anything animated per frame must keep calling `invalidate()` while it runs (see the spawn animation in `VillageMeshes.tsx`), otherwise it freezes after one frame. Exception: when the Debug perf monitor is on, the loop switches to `"always"` (r3f-perf samples through R3F's global loop callbacks, which only run on rendered frames; on `"demand"` it barely updates — tried and reverted). A still scene then redraws ~200 times a second, so its label says it renders continuously: turn it off before profiling.
- **Geometry cache**: [src/render/geometryCache.ts](../src/render/geometryCache.ts) — every geometry (box, rounded box, cylinder, extruded cell contour, window frame-with-hole, gable…) is built once per parameter combination and shared. Never mutate a cached geometry; the merge copies its attributes. `getGeo()` strips every geometry to position + normal and welds it (`mergeVertices`): cached geometries are **indexed**, and `mergeParts` copies their index with an offset (Uint16 per merged group when it fits). Only ~36 % of a village's triangle corners are unique vertices. **Merged vertex format** (`mergeParts` in `buildVillage.ts`, read by the shader in `growMaterial.ts` — change both together): position Float32 × 3, normal Int8 normalized × 3, color Uint8 normalized × 3, `aCell` Int16 × 4 = (cell pivot: x and z × 2, y × 100; fall height × 100) — pivots are on half units in plan and on hundredths in height (building level on sloping terrain), so exact — and `aSpawn` Float32: 33 bytes per vertex instead of 56. A generated 12 × 12 village is ~390 k vertices / ~15 MB (it was 1.1 M / 62 MB). The cache is an LRU bounded to 1500 entries (a full village uses ~350); cached geometries are never rendered directly, so eviction needs no `dispose()`. **Vertex budget**: `roundedBoxGeo` caps its segments by radius (1 segment for r ≤ 0.015, max 2 otherwise) — a smoothness-4 rounded box is ~2 900 vertices (non-indexed), and these tiny parts once made up ~94 % of the village's vertices for no visible gain. Keep new small decorative parts cheap (a village cell is ~1.8 k welded vertices today). Window frames use a shape-with-hole extrusion with 2 curve segments per corner (`FRAME_CURVE_SEGMENTS`: the extrusion's default made 1 200 vertices per frame, a fifth of a village, for corners of 1–2.5 cm), not CSG; CSG is used only for hollow shells (below), cached like any other geometry.
- **Ambient occlusion**: N8AO via [src/components/AmbientOcclusion.tsx](../src/components/AmbientOcclusion.tsx), imported **dynamically** by `VoxelScene` once `aoEnabled` is on, and mounted as a regular `EffectComposer` child (no `Suspense` — the composer only rebuilds its passes when its children change). The `EffectComposer` is keyed on whether the AO pass is mounted: adding a depth-texture pass to a composer that has already rendered leaves its MSAA depth renderbuffer in DEPTH24 while the texture is DEPTH32F, and the MSAA resolve blit then fails every frame on strict drivers (Metal/macOS: `glBlitFramebuffer: Depth/stencil buffer format combination not allowed`) — keep the key. `n8ao` has its own chunk group in `vite.config.ts` (`priority`, `includeDependenciesRecursively: false`); otherwise rolldown folds it (~83 kB gzip) into the startup `r3f` chunk. It is also declared side-effect free (`treeshake.moduleSideEffects`): `@react-three/postprocessing` re-exports its own N8AO effect, and without that rule the `r3f` chunk kept a bare `import "./n8ao…"`, so the chunk was preloaded and run at startup anyway — check `dist/index.html` has no `n8ao` modulepreload after touching the build config. The Tweakpane panel is `React.lazy`-loaded from `App.tsx` for the same reason. Types for `n8ao` are declared in `src/n8ao.d.ts`.
